# Storage benchmark after memory fixes — September 17, 2026

Three fresh-process runs per engine/dataset, alternating engine order, on Apple
M5 / 32 GiB / Node 24.19.0 / LMDB 3.5.6. All 12 runs verified rows before and
after reopening. Timed runs ran separately from regression tests and profiling.
Implementation: memory-fix working tree based on `ac97f49`, committed with this report.

Peak RSS fell about 49% for large rows and 28% for small rows. GC elapsed
time fell about 58% / 75% respectively. Write timings are mixed: large batch
throughput rose 2%, small batch throughput fell 13%, and single-write latency
increased. This supports the memory improvement, not a general speedup claim.

RSS includes mapped file pages and allocator slack, not just live application
data. See the [memory attribution report](memory-2026-09-17.md) for private
footprint measurements and remaining amplification. LMDB reuses deleted pages;
GC does not promise immediate filesystem shrinkage.

These are small synthetic workloads on a live workstation. Three runs do not
establish production limits or statistical significance. The original baseline
was measured on September 15; modest timing changes can include workstation
noise. No cloud latency, power loss, or production-scale database is tested.
