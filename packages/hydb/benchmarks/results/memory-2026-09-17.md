# Memory amplification fixes — September 17, 2026

The KV engine now drops superseded unpublished pages after each row mutation,
avoids redundant internal payload copies, and sweeps dead page keys without
reading their payloads. Transactions remain atomic and snapshots retain their
published roots.

## Detailed memory probe

Same large-row workload and profiling harness as the
[original investigation](memory-2026-09-15.md): 256 rows with 16 KiB payloads,
64-row seed batches, 16 MiB tree cache, native LMDB 3.5.6 on Apple M5/macOS.
One diagnostic run per implementation; these are measurements, not memory limits.

| Measurement                                 |      Before |     After |
| ------------------------------------------- | ----------: | --------: |
| Largest seed publication payload            |    67.5 MiB |   3.7 MiB |
| RSS after cleanup + JS GC                   | 1,289.3 MiB | 637.8 MiB |
| macOS physical footprint at that checkpoint |   615.4 MiB | 377.9 MiB |
| Live JS heap at that checkpoint             |    18.1 MiB |  18.2 MiB |
| RSS after close + JS GC                     |   632.4 MiB | 395.4 MiB |
| Seed-only footprint after close + JS GC     |   574.1 MiB | 318.8 MiB |

RSS includes resident mapped database pages; macOS physical footprint better
captures private memory pressure. Both improved substantially. The live JS heap
remained essentially unchanged, consistent with the original diagnosis.

Memory is still larger than the live row payload: JSON/base64 serialization,
copy-on-write tree mutations, bounded tree caching, V8 heap capacity, native
allocator slack, and LMDB mapped pages remain. This patch removes avoidable
amplification; it does not establish a constant memory bound for arbitrary
transactions or GC's live-page mark set.

## Changes and compatibility

- Staging tracks child page IDs and traces current table/index roots after each
  complete row mutation. It retains shared children and only publishes the final
  reachable pages. Published pages remain immutable.
- Tree serialization can transfer buffer ownership internally. Public KV writes
  still copy inputs before yielding, and safe LMDB reads own their buffers.
- The swappable KV interface adds snapshot-ordered `scanKeys`.
- Eight-byte page-size sidecars make GC accounting possible without dead payload
  reads. Sidecars publish/delete atomically with pages.
- Old KV databases without sidecars still collect correctly. Their reports mark
  byte accounting incomplete and count missing sizes; known byte totals are
  lower bounds.
- The obsolete profiling-only keys sweep adapter was removed.

Validation: 185 HyDB tests, two Electron runtime tests, and the HyOS check pass.
Regression coverage includes shared staged children, historical published pages,
buffer isolation, key cursor snapshots, legacy size metadata, and GC concurrency.
